## 4. NOT REPLICABLE in a self-hosted open tool — document instead

- **Official OnlyFans/Fansly automation access.** None of these tools use a public OF/Fansly API (none exists for posting/messaging). They operate via unofficial APIs, browser automation, or direct partnerships — all carry ban risk and none can be redistributed in open source. CreatorForge's manual-assist + approval-gate posture is the correct self-hosted stance; document the risk honestly.
- **Telegram Stars / paid media.** In-chat PPV via Telegram Stars is Telegram-platform infrastructure; a self-hosted tool can *drive* a Telegram bot (Bot API supports paid media) but Stars revenue share and payouts live inside Telegram. → Build a Telegram bot adapter; don't promise Stars economics.
- **Hosted AI models & GPU fleets.** Competitors' "AI chatter" runs on their servers with fine-tuned models. Self-hosted equivalent: local LLM (Ollama/LM Studio) or the user's own API keys — document both paths, never fake autonomy.
- **Streaming avatar infrastructure.** Real-time talking avatars (HeyGen/D-ID streaming) need their hosted WebRTC pipelines; self-hosted = high-latency local talking-head. Document honestly.
- **App-store / platform distribution.** SaaS tools ship browser extensions and mobile apps via stores; CreatorForge ships PWA + Expo (user builds). Document the EAS build path.
- **Managed compliance & ban-shielding.** Agencies sell "we keep your account safe" (proxies, anti-detect, human review). Can't be productized in a repo — document as operational guidance.
- **Dead ends to avoid:** PlayHT (Meta acquisition, sunset Dec 2025), LOVO/Genny (bankrupt May 2026). Do not integrate.
